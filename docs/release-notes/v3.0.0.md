## ⚠️ Breaking: minimum iOS is now 15.0

BMXCore and BMXCall now require **iOS 15.0** (previously iOS 13.0 with SPM, iOS 14.0 with CocoaPods). Xcode 27 no longer builds iOS 13/14 deployment targets, so the SDK can no longer support them.

This is why this release is a major version. If your app still targets iOS 13 or 14, stay on 2.x. With SPM, your existing `.upToNextMajor(from: "2.x")` requirement keeps you there. With CocoaPods, your Podfile pins a specific `:tag`, so nothing changes until you update it.

## Fixed

- **SDK doesn't build with Alamofire 5.10 or later** ([#10](https://github.com/runslikebutter/butterflymx-sdk-ios/pull/10)). Apps that use Alamofire 5.10+ elsewhere couldn't add the SDK: Japx's `JapxAlamofire` module (pulled in by BMXCore) fails to compile against it with `'Parameters' is ambiguous`. BMXCore no longer depends on `JapxAlamofire`, and now supports **Alamofire 5.6.1 up to (not including) 6.0.0**.

No public API changes. `APIClient.sendRequest(path:params:method:completion:)` now spells its parameter type as `Alamofire.Parameters`. It's the same type as before, so call sites don't change.

## Upgrading

1. Set your app's deployment target to iOS 15.0 or later.
2. Update your SDK requirement:
   - **SPM (Package.swift):** `.package(url: "https://github.com/runslikebutter/butterflymx-sdk-ios.git", .upToNextMajor(from: "3.0.0"))`
   - **SPM (Xcode):** in your project's **Package Dependencies**, set the `butterflymx-sdk-ios` rule to **Up to Next Major Version** from `3.0.0`.
   - **CocoaPods:** set `platform :ios, '15.0'` and point both pods at the `v3.0.0` tag, then run `pod update BMXCore BMXCall`:
     ```ruby
     pod 'BMXCore', :git => 'https://github.com/runslikebutter/butterflymx-sdk-ios.git', :tag => 'v3.0.0'
     pod 'BMXCall', :git => 'https://github.com/runslikebutter/butterflymx-sdk-ios.git', :tag => 'v3.0.0'
     ```
     List `BMXCore` with `:git` even if you only use `BMXCall`. Otherwise CocoaPods looks for BMXCall's `BMXCore` dependency on the CocoaPods trunk, where 3.0.0 isn't published.
3. If your app imports `JapxAlamofire` itself but never declared Japx as its own dependency (it was only reachable through BMXCore), add Japx to your app directly. Note that Japx 4.0.1's `JapxAlamofire` doesn't build with Alamofire 5.10+.

## Dependencies

| Dependency | 2.x | 3.0.0 |
|---|---|---|
| Alamofire | `5.6.1 ..< 5.10.0` | `5.6.1 ..< 6.0.0` |
| Japx | `Japx` + `JapxAlamofire` (CocoaPods: `Japx/Alamofire`) | `Japx` core only (CocoaPods: `Japx/Core`), `~> 4.0` |
| OAuthSwift | `~> 2.2` | unchanged |
| TwilioVideo (BMXCall) | `~> 5.8.1` | unchanged |
